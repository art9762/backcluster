# BackCluster

Локальный Qwen3.8-27B для программирования на связке **MacBook Pro M4 Pro 24 ГБ + iPad Pro 13 M5 256 ГБ + iPhone 17 Pro Max**.

Основан на [StayLameBro/backburner](https://github.com/StayLameBro/backburner). Сохраняем исходный код, историю и MIT-лицензию. Наш фокус: работа трёх разных устройств, измеряемое распределение нагрузки и освобождение памяти Mac для редактора и сборок.

**Состояние на 2026-10-09: исследование и план.** Runtime сохранён без изменений. Новые режимы ниже пока не реализованы и на целевых устройствах не проверены. Пользователь уточнил модель: **3.8**, первоначальное упоминание 3.5 было опечаткой.

## Что хотим получить

- Один локальный OpenAI-compatible endpoint для OpenCode.
- Определение каждого устройства, доступной памяти, скорости связи и нагрева.
- Режим ускорения: полный IQ4_XS на Mac, iPad помогает с prefill; iPhone участвует в длинном контексте.
- Режим распределённых весов: части модели постоянно живут на разных устройствах, оставляя Mac память для разработки и позволяя попробовать более качественную квантизацию.
- Восстановление после отключения устройства без продолжения с потерянным состоянием модели.
- Работа без интернета после установки и скачивания зависимостей.

**48 ГБ физической памяти не равны 48 ГБ доступной модели.** У каждой ОС, приложения и GPU свои лимиты. Обычный split-prefill upstream оставляет полную модель на Mac. Настоящее распределение весов требует отдельного режима.

## С чего начинаем

Воспроизводим Mac-only baseline, затем сравниваем Mac + iPhone и Mac + iPad по отдельности. После этого подключаем тройку и выбираем раскладку по времени реальной coding-задачи. Постоянная загрузка всех трёх чипов сама по себе не цель.

В этом изменении нет готовой команды `backcluster serve` или нового планировщика. [Пример профиля](profiles/apple-trio.example.json) описывает будущий интерфейс и не читается runtime. Унаследованные команды находятся в [оригинальном README](README.upstream.md); его замеры принадлежат upstream.

`llama.cpp/` остаётся submodule на закреплённом commit. После клонирования нужен `git submodule update --init --recursive`. Перед изменением engine создаём его отдельный downstream fork, затем обновляем gitlink на доступный commit.

Не используйте унаследованный `install.sh` как установщик BackCluster: он использует upstream-имя, релизы и пути. Адаптация входит в BC-030.
